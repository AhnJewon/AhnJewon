네트워크 프로토콜 스택 — ARP · 채팅/파일 전송 · 라우팅 테이블 2023 · 7인 팀 · 팀장 · 컴퓨터네트워크 A+

TCP/IP 스택의 동작 원리를 코드로 이해하기 위한 컴퓨터네트워크 과제. 수업에서 제공한 계층 뼈대(CBaseLayer · CLayerManager) 위에 Ethernet · IP · ARP · 응용 계층을 구현하고, Npcap으로 실제 NIC에서 프레임을 주고받는 프로그램 3종(채팅·파일 전송, ARP, 라우팅 테이블)을 제작.

팀장 (7인) — 계층 구현 · 일정 조율

팀 구현 내용
  • ARP 계층 — Request/Reply 처리. 캐시 엔트리마다 타이머 스레드를 붙여 Incomplete는 3분, Complete는 20분 뒤 자동 삭제. Gratuitous ARP를 송신하고, 수신 시 기존 엔트리의 MAC을 갱신
  • 파일 전송 계층 — 파일을 1448바이트 조각으로 나누고 첫 조각에 파일명·크기를 실음. 조각마다 ACK를 기다리는 stop-and-wait, 수신 측은 시퀀스 번호로 정렬해 재조립
  • 채팅 계층 — Ethernet 프레임 하나에 담기지 않는 긴 메시지를 분할 전송. 첫 프레임에 전체 길이를 싣고 수신 측에서 이어 붙여 복원
  • Npcap 송수신 스레드 — 블로킹 호출인 pcap_next_ex 수신 루프와 파일 전송을 AfxBeginThread 작업 스레드로 분리해 UI가 멈추지 않게 함
  • 라우팅 테이블 — Destination · NetMask · Gateway · Flag · Interface · Metric 엔트리 추가/삭제, 입·출력 NIC 2개 선택
설계 — 이더넷 위에서 파일을 빠짐없이 보내기

Ethernet 계층은 전달을 보장하지 않으므로, 파일 전송 계층이 직접 순서와 수신 확인을 맡았다:

  1. 보낼 파일을 미리 1448바이트 조각 리스트로 나눔. 0번 조각은 파일명·크기, 마지막 조각은 FINAL 타입으로 표시
  2. 송신 스레드는 조각을 보낸 뒤 그 시퀀스 번호의 ACK가 올 때까지 10ms 간격으로 재전송
  3. 수신 측은 조각을 받을 때마다 ACK를 돌려보내고 리스트에 쌓음
  4. FINAL 조각을 받으면 시퀀스 번호로 정렬해 파일에 기록. 진행률은 프로그레스 바로 표시
